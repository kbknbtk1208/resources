# ユーザー管理ドメイン知識

## 概要

アプリケーションにおけるユーザー管理システムの主要な概念とビジネスルールについて説明します。

## ユーザーアカウント管理

### ユーザー登録
- **メール認証**: 登録時にメール認証を必須とする
- **パスワード強度**: 最低8文字、英数字記号を含む
- **重複チェック**: メールアドレスとユーザー名の重複を防ぐ
- **利用規約同意**: 登録時に利用規約への同意を必須とする

### プロフィール情報
- **必須項目**: 名前、メールアドレス
- **任意項目**: 電話番号、住所、生年月日、プロフィール画像
- **公開設定**: ユーザーがプロフィールの公開範囲を設定可能

### アカウント状態
- `ACTIVE`: アクティブ（通常利用可能）
- `INACTIVE`: 非アクティブ（一時的な利用停止）
- `SUSPENDED`: 停止（違反行為による利用停止）
- `DELETED`: 削除済み（論理削除）

## 認証・認可

### 認証方式
- **パスワード認証**: 基本的な認証方式
- **多要素認証 (MFA)**: SMS、メール、認証アプリによる追加認証
- **ソーシャルログイン**: Google、Facebook、Twitterアカウントでの認証
- **シングルサインオン (SSO)**: 企業内システムとの連携

### セッション管理
- **セッション有効期限**: 24時間（延長可能）
- **同時ログイン制限**: 同一アカウントで最大3セッション
- **セッション無効化**: パスワード変更時に全セッションを無効化

### パスワード管理
- **ハッシュ化**: bcryptを使用してパスワードをハッシュ化
- **パスワードリセット**: メール経由でリセットリンクを送信
- **パスワード履歴**: 過去5回のパスワードの再利用を禁止
- **パスワード有効期限**: 90日（企業アカウントの場合）

## ユーザーロール・権限管理

### ロール階層
```
Super Admin
├── Admin
│   ├── Manager
│   │   └── Member
│   └── Support
└── User
    ├── Premium User
    └── Free User
```

### 基本ロール
- **Super Admin**: システム全体の管理権限
- **Admin**: 組織内の管理権限
- **Manager**: チーム管理権限
- **Member**: 一般ユーザー権限
- **Support**: サポート専用権限

### 権限管理
- **RBAC (Role-Based Access Control)**: ロールベースのアクセス制御
- **ABAC (Attribute-Based Access Control)**: 属性ベースのアクセス制御
- **リソースベース権限**: 特定のリソースに対する操作権限

### 権限継承ルール
- 上位ロールは下位ロールの権限を自動継承
- 明示的な拒否設定は継承された権限より優先
- リソース所有者は該当リソースに対する全権限を持つ

## プライバシー・データ保護

### 個人情報の取り扱い
- **データ最小化**: 必要最小限の個人情報のみ収集
- **同意管理**: データ利用目的ごとに明示的な同意を取得
- **データ保持期間**: 利用目的達成後は適切に削除
- **アクセスログ**: 個人情報へのアクセスを記録・監査

### GDPR対応
- **忘れられる権利**: ユーザーからの削除要求への対応
- **データポータビリティ**: データの移行・ダウンロード機能
- **同意の撤回**: いつでも同意を撤回可能
- **データ侵害通知**: 72時間以内の当局への通知

### データ暗号化
- **保存時暗号化**: データベース内の個人情報を暗号化
- **転送時暗号化**: HTTPS/TLSによる通信の暗号化
- **キー管理**: 暗号化キーの安全な管理

## ユーザー体験 (UX)

### アカウント作成フロー
1. 基本情報入力
2. メール認証
3. プロフィール設定（任意）
4. チュートリアル・ウェルカム画面

### ログインフロー
1. 認証情報入力
2. 多要素認証（有効な場合）
3. ダッシュボード表示
4. セキュリティ通知（新しいデバイスの場合）

### パスワードリセットフロー
1. メールアドレス入力
2. リセットメール送信
3. リセットリンクからパスワード変更
4. 変更完了通知

## セキュリティ対策

### 攻撃防止
- **ブルートフォース攻撃**: ログイン試行回数制限
- **アカウント列挙攻撃**: 統一されたエラーメッセージ
- **セッション固定攻撃**: ログイン時のセッションID再生成
- **CSRF攻撃**: CSRFトークンによる防止

### 監査・ログ
- **ログイン履歴**: 成功・失敗を含む全ログイン試行を記録
- **権限変更履歴**: ロール・権限の変更を記録
- **データアクセス履歴**: 個人情報へのアクセスを記録
- **異常検知**: 通常と異なるアクセスパターンの検知

## API設計

### RESTful API エンドポイント
```
POST   /api/auth/register          # ユーザー登録
POST   /api/auth/login             # ログイン
POST   /api/auth/logout            # ログアウト
POST   /api/auth/refresh           # トークン更新
GET    /api/users/profile          # プロフィール取得
PUT    /api/users/profile          # プロフィール更新
POST   /api/auth/password/reset    # パスワードリセット要求
PUT    /api/auth/password          # パスワード変更
GET    /api/users/permissions      # 権限情報取得
```

### 認証トークン
- **JWT (JSON Web Token)**: ステートレスな認証トークン
- **リフレッシュトークン**: アクセストークンの更新用
- **トークン有効期限**: アクセストークン15分、リフレッシュトークン7日

## データモデル

### User エンティティ
```typescript
interface User {
  id: string;
  email: string;
  username: string;
  firstName: string;
  lastName: string;
  phoneNumber?: string;
  dateOfBirth?: Date;
  profileImageUrl?: string;
  status: 'ACTIVE' | 'INACTIVE' | 'SUSPENDED' | 'DELETED';
  emailVerified: boolean;
  mfaEnabled: boolean;
  roles: Role[];
  createdAt: Date;
  updatedAt: Date;
  lastLoginAt?: Date;
}
```

### Role エンティティ
```typescript
interface Role {
  id: string;
  name: string;
  description: string;
  permissions: Permission[];
  createdAt: Date;
  updatedAt: Date;
}
```

### Permission エンティティ
```typescript
interface Permission {
  id: string;
  resource: string;        // 'user', 'post', 'comment' など
  action: string;          // 'create', 'read', 'update', 'delete'
  conditions?: object;     // 条件付き権限
}
```

## 通知システム

### 通知種別
- **セキュリティ通知**: ログイン、パスワード変更、異常検知
- **アカウント通知**: プロフィール更新、権限変更
- **システム通知**: メンテナンス、サービス更新

### 通知チャネル
- **メール通知**: 重要なセキュリティイベント
- **アプリ内通知**: リアルタイム通知
- **SMS通知**: 緊急時のセキュリティアラート
