# Eコマースドメイン知識

## 概要

Eコマース（電子商取引）システムにおける主要なドメイン概念とビジネスルールについて説明します。

## 主要エンティティ

### ユーザー (User)
- **顧客 (Customer)**: 商品を購入するユーザー
- **管理者 (Admin)**: システムを管理するユーザー
- **販売者 (Seller)**: 商品を販売するユーザー

### 商品 (Product)
- **商品カテゴリ (Category)**: 商品の分類
- **商品バリエーション (ProductVariant)**: サイズ、色などのバリエーション
- **在庫 (Inventory)**: 商品の在庫数

### 注文 (Order)
- **カート (Cart)**: 注文前の商品の一時保存
- **注文項目 (OrderItem)**: 注文内の個別商品
- **注文ステータス (OrderStatus)**: 注文の状態管理

### 支払い (Payment)
- **支払い方法 (PaymentMethod)**: クレジットカード、銀行振込など
- **支払いステータス (PaymentStatus)**: 支払いの状態

### 配送 (Shipping)
- **配送先住所 (ShippingAddress)**: 商品の配送先
- **配送方法 (ShippingMethod)**: 宅急便、メール便など
- **配送ステータス (ShippingStatus)**: 配送の状態

## ビジネスルール

### 注文プロセス
1. **商品選択**: 顧客が商品をカートに追加
2. **在庫確認**: カート内商品の在庫を確認
3. **注文確定**: 顧客情報と配送先を入力して注文を確定
4. **支払い処理**: 選択した支払い方法で決済を実行
5. **在庫減算**: 注文確定後に在庫を減算
6. **配送手配**: 倉庫に配送指示を送信

### 在庫管理ルール
- 在庫数がゼロになった商品は「売り切れ」状態に変更
- 在庫予約：注文確定時に在庫を予約し、支払い完了後に確定減算
- 安全在庫：設定値を下回った場合にアラート通知

### 価格計算ルール
```
合計金額 = (商品価格 × 数量) + 送料 + 消費税 - 割引金額
消費税 = (商品価格 + 送料) × 消費税率
```

### 割引ルール
- **クーポン割引**: 固定額割引またはパーセント割引
- **会員割引**: 会員ランクに応じた割引率
- **数量割引**: 購入数量に応じた段階的割引

### 返品・キャンセルルール
- **注文キャンセル**: 配送前であればキャンセル可能
- **返品期間**: 商品到着から14日以内
- **返品対象外商品**: 食品、カスタム商品など

## ステータス管理

### 注文ステータス
- `PENDING`: 注文受付中
- `CONFIRMED`: 注文確定
- `PROCESSING`: 処理中
- `SHIPPED`: 発送済み
- `DELIVERED`: 配送完了
- `CANCELLED`: キャンセル
- `RETURNED`: 返品

### 支払いステータス
- `PENDING`: 支払い待ち
- `PROCESSING`: 処理中
- `COMPLETED`: 支払い完了
- `FAILED`: 支払い失敗
- `REFUNDED`: 返金済み

### 在庫ステータス
- `IN_STOCK`: 在庫あり
- `LOW_STOCK`: 在庫少
- `OUT_OF_STOCK`: 在庫切れ
- `DISCONTINUED`: 販売終了

## データ整合性ルール

### 注文データの整合性
- 注文金額 = 注文項目の合計金額
- 支払い金額 = 注文金額
- 在庫減算数 = 注文項目の数量合計

### 在庫データの整合性
- 物理在庫 = システム在庫
- 予約在庫 + 利用可能在庫 = 総在庫

## セキュリティ要件

### 個人情報保護
- 顧客の個人情報は暗号化して保存
- クレジットカード情報は外部の決済代行サービスに委託
- アクセスログの記録と監査

### 決済セキュリティ
- PCI DSS準拠
- 3Dセキュア対応
- 不正検知システムの導入

## パフォーマンス要件

### レスポンス時間
- 商品検索: 2秒以内
- 注文処理: 5秒以内
- 決済処理: 10秒以内

### スケーラビリティ
- 同時接続ユーザー数: 10,000人
- ピーク時の注文処理能力: 1,000件/分
